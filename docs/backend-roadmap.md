# Backend scope and implementation milestones

## Implemented foundation

Java 21, Spring Boot 4.1.1, Spring Modulith 2.1.1, PostgreSQL, JPA/Hibernate, Flyway, Spring Security, Maven and Docker packaging.

Business modules: branches, materials, suppliers (including plants/material associations), customers (including projects/sites), orders (including preliminary dispatch weight records), fleet, fuel, purchasing/inventory and logistics. Identity module supplies database-backed authentication and user administration. Audit module supplies persistent change history. Platform module supplies CSRF and API errors. Architecture tests verify module dependencies; cross-module access uses CustomerRegistry and TruckRegistry rather than repositories.

The legacy manual-order API creates one material/service line per order. The RFQ/quotation workflow now supports multi-item orders with separate material/freight pricing and ordered-quantity billing. All quantities are tonnes and prices INR per tonne. A TRANSPORT order uses the material field as the carried-material description; legacy combined rates are preserved; separate material/freight rates are supported through quotations. Subtotal is a commercial preview excluding tax, not an invoice or accounting entry. Sales and supplier billing preparation now snapshots source quantities, rates and commercial terms for independent review. Tax invoice issuance, posting and cumulative invoice allocation remain deferred until the accountant confirms tax rules.

Fuel and operating expense submissions now support independent approval/rejection and audited revisions. Diesel master corrections retain old/new values and reasons; actual receipt prices and submitted reference snapshots remain independent. Trip summaries include approved allocated costs, not accounting profit. Consumption and tank balance are not inferred from fuel filled. Supplier and driver endpoints remain closed until record ownership is implemented.

## Before production

Configure MFA, HTTPS, branch/record permissions, shared sessions for multiple replicas, secrets management, backups with restore verification, structured monitoring and migration deployment controls. Application login lockout after five failed attempts in fifteen minutes is implemented. Production cookie settings are provided; infrastructure still needs configuration. Review dependencies and tax/accounting rules. Run PostgreSQL-backed integration tests and load testing against expected volumes. This is a development foundation, not a deployable complete ERP.
